# 交互设计方案（最终版）

> 版本: v3.0 | 2026-07-27 | 状态: 待确认
> 聚焦核心布局图绘制功能，不考虑 LLM 个性化生成。

---

## 一、用户是谁、想要什么

### 1.1 用户画像

```
普通业主 / 年轻家庭 / 租房党 / 装修小白
  ↓
真实场景：
  "我家次卧 3m×4m，有个门有个窗，
   要放床、衣柜、书桌，怎么摆合理？"
  ↓
想要的结果：
  一张能看的平面图，标好尺寸，告诉我家具怎么摆
  ↓
不想要的：
  学工具怎么用、理解模式和概念、记快捷键
```

### 1.2 用户的真实操作循环

不是线性流程，而是**反复调整的循环**：

```
设定房间 ──→ 选家具 ──→ 看布局 ──→ 调一下 ──→ 再看布局 ──→ 导出
  ↑            ↑          ↑           ↑             ↑
  └──── 随时改 ──── 随时增减 ──── 随时重排 ──── 随手微调 ────┘
```

所以界面应该让用户在任何时候都能做任何操作，而不是"必须先做完 A 才能做 B"。

## 二、交互设计原则

| # | 原则 | 含义 |
|---|------|------|
| 1 | **所见即所得** | 画布始终实时反映当前状态，操作立刻生效，没有"确认"/"应用"步骤 |
| 2 | **零模式切换** | 没有"画户型模式""放家具模式"的概念。任何时候，墙可以点、家具可以拖、门窗可以放 |
| 3 | **渐进披露** | 初级操作一目了然（模板、点击），高级操作存在但不喧宾夺主（手绘墙） |
| 4 | **安全探索** | Ctrl+Z 撤销、所有操作可逆、碰撞自动回弹——用户感觉"怎么试都不会搞坏" |
| 5 | **一致性** | 同类元素交互方式一致：选中=蓝框+手柄，拖拽=移动，边缘=调宽，Delete=删除 |

## 三、页面布局

### 3.1 整体结构

```
┌──────────────────────────────────────────────────────────────────────┐
│ [logo]  房间设置    家具选择    布局方案    微调      [AI输入框] [导出] │
│         ●活跃      ○可用       ○可用      ○可用                      │
├──────────┬───────────────────────────────────────────────────────────┤
│          │                                                          │
│ 左侧面板  │                       画布                                │
│ (240px)  │                                                          │
│          │               Konva Stage 800×600                        │
│ 内容随    │                                                          │
│ 当前标签  │       始终展示房间平面图（如果有的话）                        │
│ 变化      │                                                          │
│          │        左上角叠加: 房间尺寸 "400cm × 300cm"                │
│          │                                                          │
├──────────┴───────────────────────────────────────────────────────────┤
│  [● ● ● ○ 步骤进度]  状态提示                                  [反馈] │
└──────────────────────────────────────────────────────────────────────┘
```

### 3.2 四个标签说明

标签栏始终固定在顶部，四个标签**始终可点击**，不限制访问顺序。

```
🏠 房间设置        ← 定义房间长宽 + 门窗位置
🪑 选择家具        ← 挑选要放的家具及数量
✨ 布局方案        ← 自动排列 + 切换浏览不同方案
✋ 微调            ← 拖拽/旋转/添加/删除
```

**标签状态**：
- ● 激活态（高亮色底 + 白字）← 当前所在的标签
- ○ 可用态（文字可见，可点击）← 还未去过的步骤
- ✓ 完成态（文字旁有小勾）← 该步骤的必要操作已完成（如房间已创建、家具已选择）

### 3.3 关于"不用按顺序"的交互暗示

- 标签上没有数字编号（避免"第一步""第二步"的暗示）
- 每个标签面板底部没有"下一步"按钮（避免强迫推进）
- 用"完成态 ✓"代替禁用态（不阻止用户访问，只告知进度）
- 面板内的操作按钮直接产生效果（如"生成布局"直接出方案，不需要先跳到另一个标签）

### 4.2 三种房间创建方式

三种方式**同时可见**，但视觉优先级不同：

| 方式 | 视觉地位 | 适用用户 | 为什么放这里 |
|------|---------|---------|------------|
| 快速模板 | 首要位置，大卡片 | 大多数用户 | 80% 的用户需求就是标准房间尺寸，点一下完事 |
| 自定义尺寸 | 次要位置，折叠表单 | 知道尺寸的用户 | 给有明确尺寸的用户一个快速入口 |
| 手动绘制 | 底部，次级按钮 | 极少用户 | 保留现有能力，但不让它干扰主流路径 |

**交互细节**：

- **快速模板**：点击卡片 → 画布立即渲染该尺寸的房间矩形 + 预设门窗位置 → 卡片显示选中态（高亮边框）→ "当前房间"信息更新
- **自定义尺寸**：点击输入框 → 输入宽高（最小 100cm，最大 1000cm，步长 10cm）→ 按回车或点"创建房间" → 画布渲染 → 输入框保留数值方便微调
- **手动绘制**：点击按钮 → 按钮变为激活态（蓝色）→ 画布光标变十字 → 点击放置墙点 → 吸附 10cm 网格 → 点击回到起点闭合 → 闭合后按钮自动恢复 → 画布显示房间

> **为什么手动绘制放在底部**：目标用户是普通业主，不是 CAD 用户。绝大多数人只需要"我房间 4m×3m"这种输入方式。
> 手动绘制是为少数有异形需求或想精确控制墙角的用户准备的，放在那里但不挡路。

### 4.3 门窗放置

**不需要切换任何模式**——任何时候，只要是闭合房间，就能添加门窗。

**两种激活方式**（用户可任选）：
1. **双击墙面** → 弹出小菜单
2. **单击选中墙段** → 墙段上浮现 "+" 按钮 → 点击按钮

**弹出菜单**：
```
      ┌──────────────┐
      │  添加门  🚪  │
      │  添加窗  🪟  │
      └──────────────┘
```

选一个后，菜单关闭，该元素出现在点击位置。

**门窗的选中态交互（单击选中后）**：

```
         ←→ 拖拽边缘调宽
         ────
    ─ ─ ─┐      ┌──墙线
         │      │
   ●─────┤ 🚪   │    ← 拖拽门主体沿墙移动
         │      │
    ─ ─ ─┘      └──墙线
          \     ← 弧线指示开门方向
           \       (点击切换内外开)

  画布浮层标注: ←→ 80cm
```

| 操作 | 方式 | 反馈 |
|------|------|------|
| 沿墙移动 | 拖拽门/窗主体 | 跟随鼠标在墙段上滑动 |
| 调整宽度 | 拖拽左右边缘 | 实时显示新宽度值（40-200cm） |
| 切换内外开（仅门） | 点击弧线区域 | 弧线方向反转 |
| 切换铰链侧（仅门） | 双击门图形 | 铰链点换到另一侧 |
| 删除 | Delete 键 或 点击 × | 元素消失 |
| 取消选中 | 点击画布空白 / Esc | 手柄和浮层隐藏 |

### 4.4 面板各状态

| 画布状态 | 面板显示 | 提示文字 |
|---------|---------|---------|
| 无房间（首次打开） | 模板卡片+自定义+手动绘制 | "选择一个模板开始，或自定义房间尺寸" |
| 模板/自定义创建后 | 当前房间信息摘要 | "双击墙面添加门窗" |
| 手动绘制中 | "已添加 X 个墙点" | "点击起点或按 Enter 闭合房间" |
| 房间已创建且有门窗 | 摘要信息 + 门窗数量 | "门窗已就位" |

### 5.2 选择交互

**为什么不用拖拽到画布的方式？**
- 拖拽要求用户先决定"放哪里"——但用户这时候还不知道该放哪里
- 先选类型和数量，让系统自动排，用户再微调——更符合"先想好要什么，再看怎么摆"的思维

**每项家具卡片包含**：
- 图标 + 中文名
- 尺寸（宽×高 cm）
- 数量调节器：点击 [+] 增加，点击数字直接输入

**交互细节**：
- 点击 [+] → 数量 +1，画布上出现该家具的**半透明灰色轮廓**（放在房间右侧临时区，标注名称）
- 点击数字 → 可手动输入（1-99）
- 设为 0 → 轮廓从画布消失
- 同一种家具多件时，轮廓显示编号（如"衣柜 #1""衣柜 #2"）
- 轮廓只是占位标记，不参与碰撞检测，也不精确决定最终位置

### 5.3 画布状态

- 已有房间渲染（墙体 + 门窗，来自 Step 1）
- 已选的家具以半透明灰色轮廓显示，排列在房间右侧临时区域
- 轮廓可拖拽（只是为了在画布上大致看看大小比例，不影响最终布局）
- 增减数量时轮廓即时增减

### 5.4 "排一下"按钮

- **可用条件**：至少选了 1 件家具（数量总和 ≥ 1）
- **不可用**：按钮灰色，hover 提示"至少选一件家具"
- **点击后**：执行布局算法 → 自动跳转到"✨ 布局方案"标签并显示结果

### 6.2 布局生成

**触发方式**：
1. 从"选择家具"点"排一下" → 自动进入此页并生成
2. 在此页点"重新排一下" → 用当前家具清单重新生成

**生成过程**：算法瞬间完成（JS 纯计算 < 50ms），**不做假加载动画**。点击按钮 → 方案直接出现。

**为什么不做加载动画**：布局算法是纯前端贪心搜索，没有网络延迟。用户点击后立即看到结果，比任何加载动画都更让人觉得"快"。诚实比假装聪明好。

### 6.3 方案切换

**三种方式**：
1. 点击左侧面板的方案卡片（radio 样式）
2. 键盘 ← → 方向键
3. 画布左右边缘显示小箭头（半透明，hover 显现）

**切换即时生效**：选中方案 → 画布家具位置立即更新（400ms 平滑移动动画）。

### 6.4 画布状态

每套方案在画布上的展示内容：

```
          ┌─── 窗户 150cm ───┐
          │                   │
     ┌────┐     ┌──────┐     │
     │ 🛏️  │     │📝书桌 │     │
     │ 床  │     │120×60│     │
     │160×200│   └──────┘     │
     └────┘        │          │
        │   65cm ✓ │          │   ← 通道宽度标注
     ┌──────┐      │          │
     │🗄️衣柜 │      │          │
     │100×60│      │          │
     └──────┘      │          │
          │                   │
          └─── 🚪门 80cm ────┘
```

每个方案展示：
1. 完整的房间 + 门窗 + 家具
2. 家具上方标注名称
3. 关键通道宽度标注（绿色 ✓ 或 橙色 ⚠）
4. 不同家具用不同颜色区分（与家具定义一致）

### 6.5 方案的特点说明

面板上每个方案卡片附带：
- **一句话描述**："靠墙紧凑""分区布局""居中宽敞"
- **合规检查结果**：通道宽度、特殊约束（是否靠窗等）
  - ✓ 绿色：符合要求
  - ⚠ 橙色：需要注意但可接受
  - ✗ 红色：不合理（布局算法尽量避免，极少出现）

### 6.6 面板各状态

| 状态 | 面板 | 画布 |
|------|------|------|
| 未选家具 | "还没有选择家具，← 回去选家具" | 显示空房间 |
| 已选家具未布局 | "点击'排一下'生成方案" | 显示家具轮廓在临时区 |
| 布局完成 | 三个方案可选 | 显示完整布局 |
| 重新生成后 | 方案刷新为最新结果 | 布局更新 |

| 快速旋转 | 右键点击家具 | 步进 90° | 0/90/180/270° |
| 删除 | Delete 键 或 点击 × | 从画布和列表中移除 | — |
| 取消选中 | 点击空白区域 或 Esc | 手柄消失 | — |

**碰撞处理**：
- 拖拽过程中如果两件家具重叠 → **两者轮廓变为红色半透明**
- 释放时若仍然重叠 → **自动回弹**到最近的可用位置
- 被挤开的家具顺移到附近空闲位置
- 用户几乎感觉不到冲突——系统默默处理了

### 7.5 撤销/重做

- 快捷键：Ctrl+Z / Ctrl+Y
- 撤销栈深度：最多 50 步
- 无操作可撤销/重做时按钮变灰

## 八、跨标签状态管理

### 8.1 核心原则：每个标签独立保持状态

```
标签间跳转时:

🏠 房间设置        房间尺寸和门窗 → 始终保留
🪑 选择家具        家具清单和数量 → 始终保留（改房间后轮廓位置重置）
✨ 布局方案        当前选中的方案索引 → 保留，但家具变更后自动失效
✋ 微调            当前家具位置 → 保留，但重新布局后覆盖
```

### 8.2 状态变更传播

| 操作 | 影响 | 处理方式 |
|------|------|---------|
| 在 Step 1 改了房间尺寸 | Step 3/4 的布局结果不再有效 | 下次进入 Step 3 时自动重新生成 |
| 在 Step 2 增减了家具 | Step 3/4 的布局结果不再有效 | 同上 |
| 在 Step 3 切换方案 | Step 4 的微调结果被覆盖 | 弹出确认："当前微调将被丢弃，确定切换？" |
| 在 Step 4 做了微调 | 当前方案不再是算法原始输出 | 方案卡片显示"已自定义"标记 |

### 8.3 具体场景处理

**场景：微调了半天 → 想改房间尺寸 → 回到 Step 1 修改 → 回到 Step 3 看结果**

```
① Step 4 微调完毕
② 点击"🏠 房间设置" → 修改尺寸 400→450 → 房间更新
③ 点击"✨ 布局方案" → 系统检测到家具未变但房间变了 →
   自动重新生成方案 → 显示新方案
④ 用户切换回 Step 4 → 微调结果已被覆盖 → 显示新布局 +
   状态提示"房间尺寸已更新，布局已重新生成"
```

**场景：在 Step 3 看方案 → 突然想加个家具 → 去 Step 2 添加 → 回 Step 3**

```
① Step 3 方案 A 浏览中
② 点击"🪑 选择家具" → 面板切换，家具数量保留 → 点击 [+] 加一张椅子
③ 点击"✨ 布局方案" → 方案 A/B/C 自动使用更新后的家具清单重新生成 → 显示新方案
④ 切换方案 B → 也基于新清单生成
```

## 十一、动画约定

| 场景 | 动画 | 时长 | 缓动 |
|------|------|------|------|
| 标签切换 | 面板内容淡入淡出 | 150ms | ease |
| 选中家具 | 蓝色边框从中心扩散 | 200ms | ease-out |
| 布局切换 | 家具从旧位置滑到新位置 | 400ms | ease-out |
| 添加门/窗 | 从点击点向外展开 | 200ms | ease-out |
| 删除元素 | 缩小 + 淡出 | 150ms | ease-in |
| 碰撞回弹 | 回到最近可用位置 | 250ms | ease-out |
| 房间创建 | 墙线从中心向外画出 | 300ms | ease-out |

**原则**：动画不超过 400ms，不阻碍操作，不重复播放（如碰撞提示仅闪一次）。

## 十六、完整用户旅程示例

### 用户 A：用模板快速出图

```
1. 打开页面 → 画布上显示四个模板卡片
2. 点击"👶 儿童房 4×3m"

   → 点击床的 [+] → 数量 1 → 画布出现床的半透明轮廓
```
