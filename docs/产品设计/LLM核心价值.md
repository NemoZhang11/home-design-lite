# LLM 核心价值（设计决策支持）

> 一句话：**LLM 用来补用户的知识缺口，不是替代鼠标。**  
> 详细技术方案见 `LLM个性化定制方案.md`，本文档只讲"为什么"。

---

## 核心洞察

**编辑器已经很好用了**——建房间、放家具、拖拽微调，操作直观。

但用户打开工具时真正的问题是：

| 他在想 | 编辑器能帮他吗 |
|--------|-------------|
| "5岁男孩的儿童房应该放哪些家具？" | ❌ 不知道 |
| "床放东墙还是西墙？有什么区别？" | ❌ 不知道 |
| "1.5m 的床放得下吗？" | ❌ 不确定 |
| "这个布局合理吗？" | ❌ 没把握 |
| "还有别的摆法吗？哪个更好？" | ❌ 看不到 |

**画图工具解决的是"怎么画"，用户缺的是"画什么"和"为什么这样画"。**

---

## LLM 的不可替代价值

### 1. 补全专业知识缺口
- 自动补全标准家具尺寸（单人床 120cm、衣柜深 60cm）
- 理解空间约束（"床不要靠窗"→硬约束，"想要学习氛围"→偏好方向）
- 覆盖模板覆盖不了的场景（异形尺寸、特殊需求）

### 2. 提供决策依据，建立信心
- 每个方案附带解释：为什么这样摆、有什么好处
- 方案对比展示 trade-off：方案 A 更宽敞，方案 B 储物更多
- 硬约束检查结果可视化：✓ 通道 65cm ✓ 床不靠窗
- **用户付费买的不是"能画图"，是有人担保"这样是对的"**

### 3. 让工具从"画板"变成"设计师"

| 角色 | 传统编辑器 | 加入 LLM |
|------|-----------|---------|
| 用户说 | "我知道画什么，我自己画" | "我有个房间想改造，你帮我看看" |
| 工具 | 提供画布和工具 | 提问题、给建议、出方案、解释理由 |
| 产出 | 用户自己画的图 | AI 给的 3 套方案 + 为什么推荐 |

---

## 对技术方案的指导

这套认知直接影响 `LLM个性化定制方案.md` 中的设计决策：

| 原则 | 推导自 |
|------|--------|
| LLM 不做布局决策（约束求解器做） | LLM 负责"理解"和"解释"，不负责"计算" |
| 必须有确认卡让用户审核解析结果 | LLM 理解可能有误，用户需要确认权 |
| 方案必须带解释和 trade-off 说明 | 用户需要"为什么"才能做决定 |
| 偏好推断（宽敞度/分区/采光等） | 从用户模糊描述中提取设计方向 |
| 支持文字迭代（"把床换到东墙"） | 用户改需求时打字比拖拽更自然 |
| 逐步引导模式（信息不全时） | 用户不一定知道自己该告诉工具什么 |

---

## 一句话总结

> **LLM 接入的目标不是让用户"不用鼠标"，是让一个不懂设计的人也能做出专业的设计决策。**

与之对应，产品定位从 **"AI 家居设计工具"**（帮画图）调整为 **"AI 家居设计顾问"**（帮做决定）。
