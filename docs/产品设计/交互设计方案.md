## 一、用户与操作循环

### 用户画像

普通业主——"我家次卧 3×4m，有门有窗，要放床、衣柜、书桌，怎么摆合理？"
想要一张带尺寸的平面图，不想学工具怎么用。

### 用户的真实操作

不是线性流程，而是**反复调整的循环**：

```
设房间 ──→ 选家具 ──→ 看布局 ──→ 微调 ──→ 再看布局 ──→ 导出
  ↑          ↑           ↑          ↑            ↑
  └─ 随时改 ─┴─ 随时增减 ─┴─ 随时重排 ┴─ 随手拖拽 ─┘
```

四个标签始终可点击，不限制顺序。标签上没有数字编号，每个面板底部没有"下一步"。

## 三、画布操控（核心流畅度）

### 3.1 一键铺满画布

右下角常驻 **[⊞ 铺满画布]** 按钮，旁边显示当前缩放比例 `[83%]`。

**算法**：
```
1. 取房间包围盒宽高 (roomW, roomH)，含墙体厚度
2. 可用区域 = 画布容器尺寸 - 40px 内边距
3. scale = min(availW / roomW, availH / roomH)
4. 将 stage 缩放到 scale，平移到居中
5. 动画 300ms ease-out
6. 更新缩放比例显示
```

**触发时机**：点击按钮 / `Ctrl+0` / **创建或切换房间后自动执行一次**

### 3.2 滚轮缩放

```
以鼠标指针为中心缩放:
  factor = deltaY > 0 ? 0.92 : 1.08
  newScale = clamp(old * factor, 0.2, 4.0)
  鼠标指向点在画布上的位置保持不变
```

右下角缩放比例随滚轮实时更新：`[45%]` `[100%]` `[200%]`
双击缩放比例数字 → 重置到 100%。

### 3.3 平移画布

| 操作 | 行为 |
|------|------|
| 鼠标中键按下 + 拖拽 | 平移 |
| 空格 + 左键拖拽 | 平移（替代方案） |
| 触控板双指滑动 | 平移 |

光标：`grab` / `grabbing`。

### 3.4 完整光标表

| 场景 | 光标 | 用户感知 |
|------|------|---------|
| 画布空白区域 | `default` | "这里没东西" |

| 画布空白（平移拖拽中） | `grabbing` | "正在移动视野" |
| 墙段（hover） | `pointer` | "可以点击" |

| 门/窗边缘手柄（hover） | `ew-resize` | "左右拖拽调宽度" |
| 门弧线（hover） | `pointer` | "点击切换开门方向" |
| 家具主体（hover） | `grab` | "可以拖拽" |

**关键 UX 细节**：

切换模板或改尺寸时，**如果已有房间** → 弹出确认："当前房间将被替换，确定吗？" 点确认后再创建。防止误操作丢失已有设计。

"重置房间"按钮 → 清空当前房间回到初始状态（相当于"新建"）。

**尺寸输入规则（适用于所有尺寸输入框）**：
- 输入新数值后**按 Enter 才生效**，不实时更新
- 输入过程中画布保持原样，不会因为敲了个数字就跳动
- 按 Esc 恢复为修改前的值
- 输入非法值（非数字、超出范围）→ Enter 后提示"请输入有效尺寸"，不生效

### 三种创建方式

| 方式 | 位置 | 谁用 |
|------|------|------|
| 快速模板 | 顶部卡片 | 大多数用户，点一下即得 |

| 手动绘制 | 底部按钮 | 极少数用户，保留但不喧宾夺主 |

## 九、碰撞规则与硬性约束

### 9.1 三条核心规则

```
规则 1: 家具之间不能重叠               → 硬性约束
规则 2: 家具必须完全在房间内部          → 硬性约束
规则 3: 家具允许贴墙（背面与墙内沿平齐） → 允许但不强制
```

**规则 1 执行方式**：
- 布局算法生成时：所有家具不重叠（间距 ≥ 20cm，由 `FURNITURE_GAP` 控制）
- 手动拖拽时：重叠则红色警告，释放时仍重叠则自动回弹到最近可用位置

**规则 2 执行方式**：
- 拖拽时不可将家具拖出房间边界（边界处卡住）

**规则 3 说明**：
- 家具可以"靠着墙放"，即家具的某条边与墙内沿重合
- 这是正常摆放方式，不是重叠（衣柜、书桌通常都靠墙）
- 靠墙家具的碰撞检测边界以墙内沿为界，不延伸进墙体厚度

### 9.2 关于壁挂家具（未来扩展）

当前 5 种家具（床/书桌/衣柜/椅子/沙发）均为**落地家具**，没有壁挂类型。未来如果加入壁挂家具（搁板、吊柜、壁挂书桌），需引入标记：

```typescript
interface FurnitureDef {
  // ... 现有字段
  wallMounted?: boolean;  // true = 可安装在墙上，2D 视图覆盖墙线
}
```

- `wallMounted: false`（默认）→ 适用规则 2，家具在房间内部
- `wallMounted: true` → 允许家具覆盖墙线，碰撞检测排除墙体厚度区域

当前阶段**不做壁挂标记**，所有家具统一走规则 2。

### 9.3 门/窗与家具的干涉

家具不应堵住门/窗的开口区域：

- **门前**：家具不得放置在门前 80cm 范围内（开门区域）
- **窗前**：家具不得遮挡窗户开口（窗前可放矮柜等，但高背家具应避开）
- 当前 MVP 简化处理：布局算法中硬编码门窗前方 80cm 为禁放区

## 十三、流畅性要求

### 13.1 帧率与输入响应

| 指标 | 目标 | 测量方式 | 优先级 |
|------|------|---------|--------|
| 画布交互帧率 | 60fps 稳定 | Chrome DevTools FPS meter（拖拽/缩放/平移） | 🔴 P0 |
| 输入响应延迟 | < 16ms（一帧内） | pointerdown → 视觉反馈时间 | 🔴 P0 |
| 面板切换 | 即时切换，无白屏无闪烁 | 肉眼感知 | 🟡 P1 |
| 布局算法执行 | < 50ms | console.time | 🟢 P2（已满足） |

**帧率保障策略**：
- 所有连续事件（mousemove, wheel）通过 `requestAnimationFrame` 节流，一帧内不重复重绘
- 拖拽中不触发碰撞重算（仅用半透明红色叠加提示），释放后才做精确碰撞检测
- Konva 使用 `batchDraw` 批量更新，不逐帧调用 `draw()`
- 拖拽中不写入 localStorage，不触发 layout recompute

### 13.2 渲染性能预算

| 场景 | 安全阈值 | 优化触发线 | MVP 典型值 |
|------|---------|-----------|-----------|
| 家具 Konva 节点 | ≤ 30 件 | ≥ 20 件 | 5-15 件 |
| 墙段 | ≤ 20 段 | ≥ 15 段 | 4 段（矩形） |
| 门/窗 | ≤ 10 个 | ≥ 8 个 | 1-3 个 |
| 同帧动画 | ≤ 3 个 | ≥ 3 个自动串行 | 方案切换时批量移动 |

**超出阈值退化策略**：
- 家具 ≥ 20 件 → 隐去内联文字标签（名称、尺寸），仅保留外轮廓
- 墙段 ≥ 15 段 → 长度标注改为 hover 才显示
- 动画排队：不使用 `Tween` 叠加，改用串行动画队列

### 13.3 拖拽流畅性

| 场景 | 要求 | 禁止行为 |
|------|------|---------|
| 家具拖拽 | 鼠标/手指移动无延迟跟随 | 禁止拖拽中触发碰撞计算、布局重排、localStorage 写入 |
| 门/窗沿墙滑动 | 紧贴墙线移动，不跳帧 | 禁止每帧重新计算可移动范围（预计算） |
| 边缘手柄调宽度 | 实时拉伸，尺寸数字跟随更新 | 禁止释放前写状态 |
| 旋转手柄 | 手柄跟随鼠标角度旋转 | 禁止旋转中重绘家具内文字（仅旋转后重绘） |

### 13.4 缩放与平移

| 操作 | 实现要求 |
|------|---------|
| 滚轮缩放 | 以鼠标指针为中心，每帧通过 requestAnimationFrame 更新 stage scale |
| 缩放范围 | 0.2x ~ 4.0x，超出边界直接 clamp，不做弹性效果 |
| 缩放比例显示 | 滚轮滚动时随帧率实时更新百分比数值（无额外延迟） |
| 平移 | 空格+左键 或 中键拖拽，光标即时切换 grab / grabbing |
| 铺满画布动画 | 300ms ease-out，动画期间铺满按钮 disabled（防连点） |

### 13.5 状态切换流畅性

| 场景 | 目标 | 实现方式 |
|------|------|---------|
| 标签切换 | 面板内容 < 50ms 渲染完毕，画布不闪烁不重绘 | 面板 DOM 使用 `display: none` 切换（非 destroy/create） |
| 方案切换 | 家具 400ms ease-out 滑动到新位，不闪现 | 同一 Konva layer 内移动节点 position |
| 从微调回到方案 | 无额外加载，方案卡片即时展示 | 方案数据已缓存在 store 中 |
| localStorage 读取 | 不阻塞首帧渲染 | `requestIdleCallback` 或 `setTimeout(0)` 延迟读取 |
| localStorage 写入 | 仅在 mouseup / Enter 后写入，不频繁刷盘 | 拖拽中、滚轮缩放中不触发 |

### 13.6 首屏加载

| 指标 | 目标 |
|------|------|
| 可交互时间 (TTI) | < 2s |
| 首次绘制 (FP) | < 1s |
| 无闪烁 | 模板卡片直接渲染，不出现白屏或骨架屏闪烁 |

**策略**：
- Konva 从 CDN 加载（ESM），`<script type="module">` 不阻塞 HTML 解析
- 初始画布空时不实例化 Konva Stage，等创建房间后再初始化
- 模板卡片使用纯 CSS 渲染，零 JS 依赖
- 全部代码 gzip < 100KB（当前 68KB）

| 快捷键 | 作用 | 适用范围 |
|--------|------|---------|
| Ctrl+0 / Cmd+0 | 铺满画布 | 所有标签 |
| Ctrl+Z | 撤销上一步操作 | **所有标签，全操作覆盖** |
| Ctrl+Y / Ctrl+Shift+Z | 重做 | **所有标签** |
| Delete / Backspace | 删除选中元素 | 门/窗/家具 |

| 可撤销的操作 | 标签 | 说明 |
|-------------|------|------|
| 切换模板 / 修改房间尺寸 | 🏠 房间设置 | 撤销回到前一个房间状态 |
| 添加门/窗 | 🏠 房间设置 | 撤销: 移除刚添加的门/窗 |
| 移动门/窗位置 | 🏠 房间设置 | 撤销: 回到移动前的位置 |

| 删除门/窗 | 🏠 房间设置 | 撤销: 恢复被删除的门/窗 |
| 增减家具数量 | 🪑 选择家具 | 撤销: 恢复上一次 [+] 前的数量状态 |
| 切换方案后微调 | ✋ 微调 | 撤销: 回到微调前的布局 |

> **撤销粒度**：每次 Enter 确认或每次鼠标释放（拖拽结束）记录一个快照。拖拽过程中不记录，避免撤销栈被中间态污染。
> **撤销栈上限**：50 步，超出时丢弃最早的记录。

## 十五、其他小优化细节

### 13.1 墙面 hover 发光

鼠标移到可交互的墙段上时 → 墙段显示**淡蓝色发光轮廓**（2px glow），暗示"可以点击"。移出后恢复。
区分度：未闭合的墙点不发光（不可添加门窗）。

### 13.2 墙段长度标注

画布上每条墙段旁标注实际长度：
```
┌─── 400cm ───┐
│              │
│              │ 300cm
│              │
└──────────────┘
```
- 字体 11px，灰色，与墙线平行排列
- 创建房间后自动显示，缩放时保持可读（字号不随画布缩放改变）
- 铺满画布后确保所有标注完整可见

### 13.3 门/窗内联标签

门/窗元素上直接显示类型和宽度：
```
🚪80     ← 门宽 80cm
🪟150    ← 窗宽 150cm
```
- 标签随门/窗一起移动和旋转
- 调整宽度后标签即时更新

### 13.4 右键快捷菜单

右键点击家具 → 弹出小菜单：
```
┌──────────────┐
│ 旋转 90°     │
│ 编辑尺寸...   │
│ 删除          │
└──────────────┘
```
- 减少用户移动鼠标到侧边栏或找手柄的操作路径
- "编辑尺寸"效果同双击家具

### 13.5 选中状态跨标签保留

```
操作: 在 Step 4 选中了衣柜 → 切换到 Step 3 看方案 → 切回 Step 4
结果: 衣柜仍然处于选中态（旋转手柄、浮层标注都在）
```

选中状态的唯一清除条件：用户主动点击空白 / Esc / 选中了其他元素。**切换标签不清除选中**。

### 13.6 拖拽死区

鼠标按下后移动 **4px 以内**不激活拖拽（视为点击）。
超过 4px 才进入拖拽模式。防止点击和拖拽混淆。
