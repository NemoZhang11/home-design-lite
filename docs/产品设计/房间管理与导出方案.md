# 房间管理与导出方案

> 版本: v1.0 | 2026-07-27
> 范围：多房间保存/加载、项目主页、图片导出、缩略图
> 关联文档：[交互设计方案](./交互设计方案.md)、[产品定位与路线图](./产品定位与路线图.md)

---

## 一、概述

当前 app 只支持单个房间，数据存在单一 `localStorage` key 中，无导出功能。本文档设计多房间管理 + PNG 导出的完整方案。

**目标**：
1. 用户可以在不同房间布局之间切换和管理
2. 数据不丢失、不冲突，支持 schema 版本迁移
3. 一键导出布局图为高清 PNG
4. 为未来的付费水印方案预留接口

**非目标**：
- 多人协作/云端同步（纯本地）
- PDF 导出（P3 以后考虑）
- 布局方案分享/导入导出 JSON（P3 以后考虑）

## 二、数据模型

### 2.1 RoomSnapshot — 单房间快照

```typescript
interface RoomSnapshot {
  version: 2;

  // 标识
  id: string;                          // crypto.randomUUID()
  name: string;                        // "次卧改儿童房"
  roomType: 'living' | 'bedroom' | 'study' | 'custom';
  createdAt: string;                   // ISO 8601
  updatedAt: string;

  // 几何数据（从当前 v1 SaveData 迁移）
  wallPoints: Point[];
  isClosed: boolean;
  doors: Door[];
  windows: Window[];
  furnitureItems: FurnitureItem[];
  nextWallId: number;
  nextDoorId: number;
  nextWindowId: number;

  // 布局状态
  activeScheme: number;                // 当前选中方案索引
  lastMode: 'draw' | 'place' | 'layout';  // 恢复时回到上次模式

  // 缩略图（懒生成）
  thumbnail?: string;                  // data:image/png;base64,...
}
```

### 2.2 ProjectData — 顶层容器

```typescript
interface ProjectData {
  version: 2;
  activeRoomId: string | null;
  rooms: Record<string, RoomSnapshot>;
}
```

### 2.3 与现有 SaveData 的差异

| 维度 | 现在 (v1) | 未来 (v2) |
|------|-----------|-----------|
| 存储范围 | 单房间 | 多房间 |
| 版本号 | 无 | `version: 2` |
| 房间名 | 无 | `name` + `roomType` |
| 时间戳 | 无 | `createdAt` + `updatedAt` |
| 缩略图 | 无 | `thumbnail`（可选） |
| 状态记录 | 无 | `activeScheme` + `lastMode` |

## 三、存储策略

### 3.1 选择 localStorage 的理由

| 方案 | 反对理由 |
|------|----------|
| ~~IndexedDB~~ | async API 会污染整个保存/加载链路；MVP 房间数远不到 5MB 上限 |
| ~~文件系统~~ | 浏览器无直接 FS 权限，需要 File API + 用户手动操作，体验割裂 |
| **localStorage** ✅ | 和现有 auto-save 无缝衔接；JSON blob 10 个房间 < 100KB；迁移成本最低 |

**何时迁移到 IndexedDB**：检测到 JSON 序列化后超过 4MB 时提示，或用户明确创建 50+ 房间。

### 3.2 Key 结构

| Key | 内容 | 说明 |
|-----|------|------|
| `hdt-project` | `ProjectData` JSON | 所有房间数据（单个 key，原子读写） |

单个 key 保证读写原子性——不存在"部分房间写成功、部分失败"的情况。

### 3.3 自动保存策略

| 时机 | 行为 | 说明 |
|------|------|------|
| 用户操作后 | 500ms debounce 写 `hdt-project` | 和现有逻辑一致，改为写整个 project |
| 切换房间时 | 立即保存当前房间 | 保证切换时数据不丢 |
| `beforeunload` | 同步保存 | 页面关闭前兜底 |
| 后台每 30s | 仅当 `isModified` 时保存 | 防频繁无用写 |

缩略图不在自动保存中生成——仅在**手动保存**或**切出房间时**生成（见第六节）。

## 五、图片导出

### 5.1 技术方案

基于 Konva 原生 `stage.toDataURL()`：

```typescript
stage.toDataURL({
  mimeType: 'image/png',
  pixelRatio: 2,        // Retina 2x，导出的图清晰
});
```

### 5.2 导出前处理

导出前必须做 4 件事：

| 步骤 | 原因 |
|------|------|
| `overlayLayer.hide()` | 隐藏选择柄、旋转柄、尺寸标签——导出图里不应出现 |
| `previewLayer.hide()` | 隐藏门窗放置时的 ghost 预览 |
| 缩放/平移 reset | 导出**完整房间全景**，不受当前视口位置影响 |
| `gridLayer` 可保留 | 网格有助于理解尺寸，默认保留 |

### 5.3 导出流程

```
用户点击 [导出]
    │
    ▼
导出预览弹窗：
┌─────────────────────────────────┐
│  导出方案                      │
│                                 │
│  ┌─────────────────────────┐   │
│  │                         │   │
│  │   导出的 PNG 缩略图预览  │   │
│  │   800×600               │   │
│  │                         │   │
│  └─────────────────────────┘   │
│                                 │
│  ○ 1x 标准  ● 2x Retina(推荐) │
│  ☑ 包含尺寸标注                 │
│  ☑ 包含网格                     │
│                                 │
│  [下载 PNG]                     │
└─────────────────────────────────┘
```

### 5.4 付费设计（预留）

| 等级 | 导出选项 | 实现方式 |
|------|----------|----------|
| 免费 | 1x 分辨率 + 右下角 "由 HomeDesign 生成" 水印 | 导出前在 overlayLayer 角落加 Konva.Text |
| 付费 (9.9元/月) | 2x Retina + 无水印 + 可选包含房间名/日期 | 跳过水印添加步骤 |

**水印实现**：导出前在 overlayLayer 临时添加 `Konva.Text('Made with HomeDesign')`，导出后移除。

### 5.5 导出配置默认值

| 参数 | 默认值 | 用户可选 |
|------|--------|----------|
| pixelRatio | 2 (Retina) | 1x / 2x |
| 包含尺寸标注 | true | 可关闭 |
| 包含网格 | true | 可关闭 |
| 水印 | 免费版: 有 / 付费版: 无 | — |
| 文件名 | `{房间名}_{日期}.png` | — |

## 六、缩略图策略

### 6.1 生成时机

| 时机 | 是否生成 | 原因 |
|------|----------|------|
| 自动保存 (500ms debounce) | ❌ 不生成 | 太频繁，不必要的性能开销 |
| 切出房间时 | ✅ 生成 | 唯一"用户即将看不到当前房间"的时刻 |
| 手动保存时 | ✅ 生成 | 用户明确表示"我要保存了" |
| 新建房间时 | ❌ 不生成 | 空房间无需缩略图 |

### 6.2 技术实现

和导出 PNG 完全相同，区别在于：
- `pixelRatio: 0.25`（800 × 0.25 = 200px 宽）
- 不包含水印
- 结果存 `RoomSnapshot.thumbnail` 字段（~5-10KB data URI）

## 七、数据迁移

### 7.1 v1 → v2 迁移

**触发条件**：加载时检测 `localStorage['home-design-tool-state']` 存在。

**迁移步骤**：
1. 读取旧 `SaveData`
2. 构造 `RoomSnapshot`：
   - `id` = `crypto.randomUUID()`
   - `name` = "未命名房间"
   - `roomType` = `'custom'`
   - `createdAt` = `updatedAt` = `new Date().toISOString()`
   - 其余字段直接从 `SaveData` 复制
3. 删除 `localStorage['home-design-tool-state']`
4. 写入 `localStorage['hdt-project']`（仅包含迁移后的单个房间）
5. 显示项目主页，选中该房间

### 7.2 未来升级

每个 RoomSnapshot 带 `version` 字段，后续升级走 migration 函数：

```typescript
function migrateV2ToV3(data: any): RoomSnapshot { ... }
function migrateV3ToV4(data: any): RoomSnapshot { ... }
```

加载时检测 `data.version !== CURRENT_VERSION` → 执行迁移链。
