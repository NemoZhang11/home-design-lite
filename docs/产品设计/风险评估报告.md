# home-design-tool AI家居设计助手
## 风险评估报告 + 分阶段执行清单（务实版，无美化）

> ⚠️ 本文档创建后项目已推进：工程化重构完成、GitHub Pages 已上线。核心风险判断不变，执行清单中的 Phase 0→Phase 1 之间已插入 Phase 0.5-0.6（工程化+上线准备）。详见 `PROGRESS.md`。

### 一、总览
项目定位：面向普通业主的单房间AI自动布局网页工具，区别于酷家乐（太重）、Planner5D（付费锁功能），核心卖点：一句话描述需求，自动出多套布局，仅少量手动微调。
整体结论：赛道有真实需求，但高度依赖两项核心技术验证；风险全部可控，前提是严格小步验证，不提前投入UI、移动端适配、商业化开发。

---

## 第一部分：三大核心风险逐条评估（发生概率+影响+应对方案）
### 风险1：技术风险（最高优先级，决定项目生死）
1. 风险描述
- 通用LLM对中文空间约束理解不稳定，口语化描述（不靠窗户、留出过道、衣柜贴墙角、书桌对着墙）翻译成结构化约束JSON时出错；
- 替换贪心算法的约束求解器，多家具、多约束下出现排布拥挤、动线不合理、局部卡死，方案看着合格但没法实际入住；
- 前端Konva画布和AI引擎对接后，坐标、尺寸单位不统一，方案导入错乱。
2. 发生概率：中高
3. 影响：核心卖点失效，产品变成一个普通开源绘图玩具，没有差异化，无法变现。
4. 止损边界与应对（对应原定4阶段）
- 阶段1只做离线测试：收集100条真实用户口语化房间需求，只跑LLM解析，不做前端联调；解析准确率达不到85%直接停止项目，沉没成本极低（仅prompt调试，月费几百元）；
- 阶段2独立开发求解引擎，限定场景：只支持3~6件家具的小房间（儿童房、次卧），不做全屋、异形户型；只约束硬性规则：不重叠、最小过道80cm、禁放区（窗户、门开口），不加入审美、风水等模糊条件，大幅降低求解难度；
- 求解结果人工盲测：找10个普通人打分，可用方案低于60%，放弃自研求解器，改用开源布局库替代。
5. 结论：技术可以实现，但必须缩小场景边界，不能追求万能AI。

### 风险2：移动端体验风险（次高优先级，决定留存）
1. 风险描述
用户绝大多数场景在手机打开网页，触屏拖拽墙体、微调家具极易误触；屏幕过小，精细编辑体验很差，用户用一次就放弃。
2. 发生概率：很高
3. 影响：网页功能再好，移动端无法使用，留存极低。
4. 务实解决方案（不追求手机全能编辑）
- 产品交互逻辑彻底重构：手机端只做三件事：输入文字需求、查看AI生成方案、点选切换不同方案；
- 把精细编辑功能完全交给PC端；手机不开放自由手绘户型，仅支持尺寸输入+AI自动生成户型；
- 触屏优化：放大所有交互热区，区分拖拽平移画布和选中家具，屏蔽浏览器默认滚动；移动端自动简化界面，隐藏全部高级工具栏；
5. 止损边界：不投入大量时间做移动端精细化编辑，接受“手机看方案、电脑改细节”的混合模式，放弃全触屏操作幻想。

### 风险3：市场与商业化风险（中等优先级，决定能不能赚钱）
1. 风险描述
- 需求是伪需求：用户只是好奇AI出图，但不愿意为方案付费；
- 竞品挤压：酷家乐、三维家不断推出AI一键布局功能，凭借品牌流量碾压；
- 流量分散：普通业主很难主动搜到这个小众工具，自然流量极低。
2. 发生概率：中
3. 影响：产品做出来没人用，有用户但无收入，长期无法覆盖服务器和LLM成本。
4. 应对方案
（1）验证需求真伪：不先做完整产品，先用图文形式在小红书、抖音发案例：“一句话生成儿童房6套布局”，只放效果图，挂一个表单收集意向邮箱；一周表单量低于200，证明需求不足，终止开发。
（2）差异化壁垒：大厂做通用全屋设计，我们只死死咬住单间改造（儿童房、书房、阳台、出租屋次卧），垂直深耕，不和大厂正面竞争。
（3）变现模式放弃高期望，采用三层稳妥结构：
① 免费层：AI生成3套方案、2D查看永久免费，用来引流；
② 付费核心（9.9元/月）：6套以上方案、无水印导出图纸、微调解锁；不设置高价年费，降低心理门槛；
③ 被动收入（不靠用户付费）：方案内家具挂载京东、淘宝联盟链接，拿佣金，即使付费转化率低，也有基础现金流覆盖LLM每月100~300元成本。
5. 底线：仅靠会员不用追求高利润，目标做到收支平衡即可，佣金作为主要盈利来源。

### 风险4：隐性次要风险
1. LLM调用不稳定、限流：解决方案：本地缓存高频句式，大部分标准化需求不走API，只处理自定义口语描述；
2. 开源竞品抄袭：把底层编辑器开源，AI布局模块闭源，既拿开源流量，又保住核心壁垒。

## 第二部分：分阶段执行清单（8~16周，严格按顺序，不并行开发）
### 阶段一：LLM自然语言解析验证（2~3周，最低成本试错）
目标：只验证语义理解，不写前端代码
1. 整理120条真实用户语料（小红书改造文案、业主常见提问）；
2. 编写分层Prompt：先提取房间尺寸、家具列表、约束条件（禁放区域、过道要求），输出标准化JSON；
3. 离线批量测试，统计解析正确率；
4. 验收标准：准确率≥85%进入下一阶段；不达标直接终止项目，无额外损失。

### 阶段二：约束求解布局引擎开发（3~5周，核心技术壁垒）
目标：替换贪心算法，产出符合居住逻辑的排布
1. 限定约束范围：仅矩形房间、矩形家具，禁止异形几何体；
2. 硬约束规则固化：家具不重叠、门前方预留1.2m通道、窗户区域禁放大件家具、最小过道0.8m；
3. 求解器纯前端JS运算，不上云，零算力成本；
4. 批量生成50组案例，普通人盲测，可用方案比例≥65%方可继续；
5. 不加入美学、动线优化等复杂逻辑，先保证能用。

### 阶段三：编辑器API封装与界面适配（3~4周）
1. 将现有Konva原型封装API，支持JSON方案一键导入画布；
2. 做响应式页面：移动端简化模式、PC完整模式；
3. 实现核心流程：输入文字→后端解析→前端求解→自动渲染多套方案；
4. 移动端只做预览和切换，不开发精细触屏编辑。

### 阶段四：端到端真实场景验证+最小商业化（2~4周）
1. 上线极简网页，部署免费静态页面（Vercel/Netlify，服务器成本为0）；
2. 接入付费订阅、商品联盟链接；
3. 投放少量内容测试流量，观察留存、点击率、佣金数据；
4. 最终验收：每月佣金+会员收入，大于LLM月度开销（300元），项目自洽成立。

---

## 第三部分：止损红线（满足任意一条，立刻停止开发，及时收手）
1. 阶段一LLM解析准确率低于80%；
2. 阶段二布局方案人工可用率低于60%；
3. 最小MVP上线后，两周自然访问量小于100人；
4. 连续两个月总收入无法覆盖300元LLM费用。

---

## 第四部分：最终务实判断
1. 做出来没问题，不存在技术鸿沟，只是需要收敛场景，不做全能工具；
2. 不用追求手机精细编辑，靠AI全自动生成绕过触屏短板；
3. 不会变成爆品，但可以做成一个自给自足的小众工具，覆盖成本并有稳定小额收益；
4. 整个验证周期成本极低，只有少量LLM费用，没有人力之外的硬性投入，试错风险完全可控。
