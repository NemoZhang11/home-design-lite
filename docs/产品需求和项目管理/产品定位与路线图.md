# home-design-tool — 产品定位与路线图

> 更新日期：2026-07-26 | 状态：规划中，待 Phase 1 验证通过后正式启动

---

## 一、产品一句话定位

**AI 家居设计助手**：面向普通业主的单房间 AI 自动布局网页工具。用户用一句话描述需求，自动生成多套布局方案，仅需少量手动微调。

---

## 二、目标用户

| 类型 | 场景 | 核心需求 |
|------|------|---------|
| 年轻家庭 | 把次卧改成儿童房 | 功能布局合理，安全，有玩耍空间 |
| 租房党 | 布置出租屋单间 | 花最少的钱让房间好用 |
| 装修小白 | 书房/阳台/客厅局部改造 | 不知道家具怎么摆，需要 AI 给出专业建议 |

**不是目标用户**：
- 专业室内设计师（需要全屋、3D、施工图）
- 需要从零开始全屋设计的业主
- 习惯用手绘或 CAD 的资深用户

## 四、移动端策略决议

**结论：不做独立移动版，做一套响应式 Web。**

### 决策依据

用户在手机上的真实路径大概率是：

```
小红书/抖音看到案例 → 手机点开链接 → 简单体验 →
  → 感兴趣 → 收藏 → 回家打开电脑 → 认真改方案
```

手机是第一触达点，但不是操作主阵地。

### 两套视图

| 设备 | 定位 | 能力 |
|------|------|------|
| **PC / 平板（宽屏 ≥ 1024px）** | 主操作平台 | 完整编辑器：画墙、放家具、拖拽微调、查看方案 |
| **手机（窄屏 < 1024px）** | 体验入口 | 输入需求 → 看方案 → 切换对比 → **不能自由编辑** |

### 开发原则

1. **Phase 1-2 完全不看手机** — Chrome 开发者即可，不花任何时间适配
2. **Phase 3 上线前花 1-2 天做响应式** — 纯 CSS + 窄屏隐藏编辑器面板，不是"做移动版"
3. **不接受以下投入**：开发微信小程序、React Native、独立的移动端 HTML 页面
4. **Phase 4 看数据决策**：如果手机流量 > 70% 且用户强烈要求，再评估是否加强移动端体验

## 五、分阶段开发路线图（8~16 周）

### 阶段概览

```
Phase 1 (2-3周)        Phase 2 (3-5周)        Phase 3 (3-4周)        Phase 4 (2-4周)
┌──────────────┐      ┌──────────────┐       ┌──────────────┐       ┌──────────────┐
│ LLM解析验证   │  →   │ 约束求解引擎  │   →   │ API封装+界面  │   →   │ 端到端验证    │
│              │      │              │       │              │       │ +最小商业化   │
├──────────────┤      ├──────────────┤       ├──────────────┤       ├──────────────┤
│ 纯文本实验    │      │ 核心算法     │       │ 系统集成     │       │ 真实场景测试  │
│ 不动编辑器    │      │ 不动UI       │       │ 上线MVP      │       │ 数据验证     │
└──────────────┘      └──────────────┘       └──────────────┘       └──────────────┘
  验证"LLM能           验证"布局排得          验证"端到端能           验证"有人用、
  听懂中文需求"         合不合理"              跑通"                  能自给自足"
  ↓ 不通过则终止        ↓ 不通过则降级         ↓ 推迟移动端            ↓ 决定项目生死
```

### 详细阶段

#### Phase 1 — LLM 自然语言解析验证（2-3 周）

**目标**：只验证语义理解，不写前端代码。成本仅 LLM API 费。

- 整理 120 条真实用户语料（小红书改造文案、业主常见提问）
- 编写分层 Prompt：提取房间尺寸、家具列表、约束条件 → 输出标准化 JSON
- 离线批量测试，统计解析正确率
- **验收标准**：准确率 ≥ 85% 进入下一阶段；不达标直接终止项目
- **投入**：仅 prompt 调试，月费约 ¥300

#### Phase 2 — 约束求解布局引擎（3-5 周）

**目标**：替换 demo 中的贪心算法，产出符合居住逻辑的布局。

- **场景限定**：仅矩形房间、3-6 件矩形家具、小房间（儿童房/次卧/书房）
- **硬约束规则**：不重叠、门前预留 1.2m、窗户禁放大件、最小通道 0.8m
- **不含软约束**：不做美学评分、不动线优化、不做风水规则
- **纯前端 JS 运算**，零服务器算力成本
- **验收标准**：50 组案例盲测，"可用+微调可用" ≥ 65%
- **止损**：低于 60% → 放弃自研，改用开源布局库

#### Phase 3 — 编辑器 API 封装 + 界面适配（3-4 周）

**目标**：打通从输入到出图的完整链路。

- 将现有 Konva demo 封装为可编程 API，支持 JSON 方案一键导入画布
- 响应式布局：PC 完整编辑器 + 手机简化视图（只看方案不编辑）
- 实现核心流程：输入文字 → LLM 解析 → 约束求解 → 自动渲染多套方案
- 手机端能力限定：输入需求、查看方案、切换方案——不做触屏编辑
- **验收标准**：3 个完整用例端到端跑通（从输入到方案渲染）

#### Phase 4 — 端到端验证 + 最小商业化（2-4 周）

**目标**：验证真实用户是否买单，项目能否自给自足。

- 部署极简页面（Vercel/Netlify，托管成本 ¥0）
- 接入付费订阅（9.9 元/月）+ 电商佣金（京东淘宝联盟）
- 投放少量内容测试流量
- **验收标准**：月收入 > LLM 月开销（¥300）
- **止损**：两周自然访问 < 100 人或连续两月收入 < ¥300 → 停止开发

## 六、MVP 功能范围（对应 Phase 3 交付）

### ✅ 做（严格限定）

- 矩形房间，尺寸通过输入数字生成（不开放手绘墙）
- 3-6 件矩形家具（床、书桌、衣柜、椅子、沙发、书架）
- 门/窗位置作为结构化输入传入（不是 AI 推理）
- AI 生成 3 套布局方案，用户可左右切换查看
- 每套方案展示俯视平面图 + 关键尺寸标注
- 用户可在 PC 上微调（拖拽家具位置）
- 付费解锁 6 套以上方案 + 无水印导出

### ❌ 不做（明确排除）

- 异形/弧形房间
- 非矩形家具（L 型沙发、转角书桌等）
- 3D 渲染（坚持 2D 平面图）
- 微信小程序 / React Native / 任何独立移动应用
- 用户注册/登录系统（MVP 阶段不做账号）
- 施工图、水电图、材料清单
- 室内风格/配色建议
- 全屋多房间布局

### ⏸ 延后（视数据决定）

- 移动端触屏编辑能力
- 自定义家具尺寸/类型
- 户型导入（拍照识别）
- 社交分享/社区功能
- 历史方案保存

## 七、商业化框架

| 层 | 内容 | 定价 | 目标 |
|----|------|------|------|
| 免费层 | AI 生成 3 套方案、2D 查看 | ¥0 | 引流，积累用户 |
| 基础付费 | 6+ 套方案、无水印导出、微调解锁 | 9.9 元/月 | 覆盖 LLM 成本 |
| 被动收入 | 方案内家具挂载联盟链接 | 佣金 | 主要盈利来源（不依赖付费率） |

**底线思维**：不追求高利润，目标做到收支平衡（月收入 > ¥300 即可自洽）。
